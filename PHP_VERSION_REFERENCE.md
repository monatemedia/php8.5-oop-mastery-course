# PHP Version Reference
> Which features this course uses, and when each one arrived.

The course targets **PHP 8.5** and makes no apology for it. But most working developers are on
something older — Laravel 13 recommends 8.4, plenty of production systems sit on 8.1 or 8.2,
and shared hosting lags further still.

So this table exists to answer the question that actually matters when you go back to work:

> **"I just learned this. Can I use it on Monday?"**

Every feature below is used somewhere in the course, with a count of how many times. Nothing
here is speculative — the list was generated by scanning the 198 course files, not written from
a changelog.

---

## The convention

When a lesson introduces a feature newer than **PHP 8.0**, it says so inline:

```php
// Asymmetric visibility — PHP 8.4. On 8.3 and below, use a private property
// with a public getter.
public private(set) string $email = '';
```

Two reasons this matters more than it looks:

1. **You will read older code.** Knowing that constructor promotion arrived in 8.0 tells you
   instantly why a 2019 codebase assigns every property by hand — that is not bad style, it is
   a language limitation.
2. **You will write code for older runtimes.** Knowing that property hooks need 8.4 means you
   know to reach for a getter instead, rather than discovering it from a parse error on
   deployment.

## What this means if you are stuck on an older version

| Your PHP | What you lose | Practical effect |
|---|---|---|
| **8.4** | The five 8.5 features above | Six lessons need reading rather than running. Everything else works. |
| **8.3** | The above, plus property hooks and asymmetric visibility | Lessons 1.1 and 2.2 become conceptual. Use getters and setters instead. |
| **8.2** | Also `#[\Override]` on methods, typed class constants | Minor. Drop the attribute; the technique is unaffected. |
| **8.1** | Also `readonly class` | Write `readonly` on each property individually. |
| **8.0** | Also enums, `readonly`, intersection types, `never` | Significant. Enums become class constants; immutability becomes a convention rather than an enforced rule. |

**None of this changes the architecture.** Dependency injection, composition over inheritance,
the SOLID principles, test doubles and container lifecycles are not version-dependent — they
predate PHP 8 entirely and will outlive PHP 9. The syntax gets more pleasant with each release;
the design decisions do not change.

That is worth saying plainly, because it is the actual reason to learn this material. The
features are how you express the ideas. The ideas are the point.

## Verifying this yourself

`verify.php` probes each 8.4/8.5 feature by executing it, so if any claim here is wrong for
your build, it will say so:

```bash
php verify.php
```

To regenerate the usage counts after adding lessons, scan the source rather than trusting this
file — it is a snapshot, and snapshots go stale.
